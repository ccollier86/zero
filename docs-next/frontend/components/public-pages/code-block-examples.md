# Compact Examples And Package-Manager Controls

[Public-page index](./index.md) · [CodeBlock overview](./code-block.md)
· [Frontend index](../../index.md) · [Documentation index](../../../index.md)

Use the same highlighted source and awaited copy operation for inline command
blocks, multi-file examples, and package-manager variants. These components do
not execute shell commands, install dependencies, create files, or manage an app.

## Minimal Examples

```tsx
import { CodeBlockInline, CodeBlockCopyText, CodeBlockPackageManager } from '@zero/framework/components/code-block';

export function InstallExamples() {
  return <section>
    <CodeBlockInline code="bun add @zero/framework" language="bash" />
    <CodeBlockCopyText content="bun add @zero/framework" size="xs" />
    <CodeBlockPackageManager command="@zero/framework" />
    <CodeBlockPackageManager command="some-tool init" type="dlx" mode="select" />
  </section>;
}
```

`CodeBlockInline` defaults to a headerless, copyable snippet with line numbers
off. It accepts normal CodeBlock props. `CodeBlockCopyText` uses the existing
morphing text primitive and defaults the copy variant to `morph`; ordinary
copy-button props still apply. Both remain [tokenized compositions](./code-block-composition.md),
not independent clipboard/highlighter engines.

## Package-Manager API

`CodeBlockPackageManager` supports:

| Prop | Type / default |
| --- | --- |
| `command` | Required string of arguments after the manager's command prefix |
| `type` | `install` (default), `dlx`, or `run` |
| `mode` | `tabs` (default) or `select` |
| `managers` | Optional readonly list of `bun`, `npm`, `pnpm`, `yarn`; default all in that order |
| `defaultValue` | `bun`; initial local choice |
| `value` / `onValueChange` | Optional controlled choice/change notification |
| `persist` | `false` (default), `true`, or a local-storage key string |
| Other CodeBlock props | Styling, copying, callbacks, and highlighting; source/files/language are generated by this composition |

Tabs use ordinary file-tab keyboard semantics. Select mode uses Zero's native
radio dropdown with checked choice, focus/touch behavior, and collision handling.
Both modes show and copy the same manager-specific command. Invalid/duplicate
manager entries are removed; an empty usable list falls back to all four.
An unavailable current choice displays the first allowed manager.

| Manager | install | dlx | run |
| --- | --- | --- | --- |
| Bun | `bun add` | `bunx --bun` | `bun run` |
| npm | `npm install` | `npx` | `npm run` |
| pnpm | `pnpm add` | `pnpm dlx` | `pnpm run` |
| Yarn | `yarn add` | `yarn dlx` | `yarn run` |

These prefixes do not validate a user's shell input. Use explicit file examples
for manager-specific arguments rather than trying to parse/rewrite shell source.

## Optional Preference And Custom Controls

`persist=true` selects `zero:code-block:package-manager`; a string chooses an
application-owned key. Persistence is never implicit. Opted-in examples share
same-tab changes and receive storage events from other tabs. Without persistence,
a saved key does not influence an example and its selection writes nothing.

SSR first uses the configured default. Storage is read after hydration, so
server markup does not depend on a browser-only value. Controlled `value`
remains authoritative even if a saved preference differs. Blocked browser
storage retains in-memory behavior and emits
`FRONTEND_CODE_PREFERENCE_FAILED`, without logging source or credentials.
A preference is not a tenant setting or backend policy.

```tsx
import { CodeBlockPackageManager, CodeBlockPackageManagerSelector,
  useCodeBlockPackageManager } from '@zero/framework/components/code-block';

export function SharedPreferenceExamples() {
  const preference = useCodeBlockPackageManager({ persist: 'example-docs:package-manager' });
  return <section>
    <CodeBlockPackageManagerSelector value={preference.value} onValueChange={preference.setValue} />
    <CodeBlockPackageManager command="@zero/framework" value={preference.value}
      onValueChange={preference.setValue} mode="tabs" />
  </section>;
}
```

The standalone selector accepts `value`, `defaultValue`, `onValueChange`,
`persist`, and `managers`; it can manage local state on its own.
`useCodeBlockPackageManager(options)` returns `{value,setValue}`.
`CODE_BLOCK_PACKAGE_MANAGERS` lists the supported names.
`getCodeBlockPackageCommand(manager,command,type?)` returns a display/copy string.

## Authority And Compatibility

Neither visual lane nor a manager choice grants platform authority. Render only
already-authorized source; do not place tokens or private records in public
examples. There are no database mutations, app configuration imports, external
provider calls, or command execution. Preferences are optional browser UI state.
The original CodeBlock `code`/`files` usage remains valid; these are additive
parts, not a requirement to rewrite existing pages.
